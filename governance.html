AI Governance & Regulatory Alignment

How this Agentic AI system addresses risk governance, model limitations, and Singapore regulatory standards.

1. Regulatory Context (MAS)

This system is designed in alignment with the Monetary Authority of Singapore (MAS) guidelines on use of Artificial Intelligence and Data Analytics (AIDA) in financial services, including the FEAT principles:

Fairness Ethics Accountability Transparency

All AI-generated recommendations are labelled clearly as model outputs, not licensed financial advice.

2. Model Risk Governance

  • ARIMA models assume stationarity and may underperform during structural breaks or market crises.
  • News sentiment is generated via a large language model (Groq / LLaMA) and may not reflect real-time news accurately.
  • VaR is a historical simulation and does not capture tail risks beyond the estimation window.
  • All models should be periodically backtested and recalibrated against out-of-sample data.

3. Agentic AI Workflow Controls

  • The agent follows a deterministic step sequence (Plan → Fetch → Risk → Forecast → Sentiment → Synthesise) to ensure auditability.
  • Each tool invocation is logged in the agent reasoning steps visible to the user.
  • Human-in-the-loop: final investment decisions remain with the human user; the agent only provides a signal.
  • Failure modes (e.g., API outages) are handled with fallback methods to ensure the workflow completes.

4. Bias & Fairness Considerations

  • LLM sentiment analysis may reflect biases present in the training data of the underlying model.
  • The system is trained/configured only on publicly available financial data; no insider information is used.
  • Recommendations are framed as signals, not certainties, to avoid over-reliance by end users.

5. Failure Cases & Mitigations

  • Risk ARIMA overfitting on short series → Mitigation Use minimum 60 data points; linear fallback if model fails.
  • Risk LLM hallucination in sentiment → Mitigation Output is clearly labelled as AI-generated; user is prompted to verify.
  • Risk Data feed outage → Mitigation Simulated fallback data with clear disclosure note.
  • Risk User over-reliance on Buy/Hold/Sell signal → Mitigation Prominent disclaimer on every results page.

6. Data Privacy

No user financial data is stored persistently. Stock data is fetched in real-time from public APIs (Yahoo Finance). Session data is used only to personalise the UI within a single session.
